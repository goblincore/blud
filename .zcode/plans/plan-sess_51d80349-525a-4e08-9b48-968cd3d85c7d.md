# Fix disconnected SDF character shadows

## Diagnosis (verified in code)

Character shadows are NOT cast by the visible body — they come from a proxy: `occluder-hull.ts` builds an inflated sphere-chain (inflate 1.15, span step 0.75) from the posed flesh prims each tick, and the flashlight's spot shadow map (`dungeon-lighting.ts:115-117`) rasterizes that twin onto walls/floor. "Disconnected" has three verified mechanisms, plus the shoulder pop the user spotted:

1. **Half-rate desync** — on hold frames the visible marched flesh is the *previous* frame reprojected, but `occluderHull.update()` (`game-main.ts:3783`) still rebuilds the shadow twin from the *current* rig pose every tick (`posed()` is always current; only the visual pose holds). The shadow leads the body by one sub-frame — most visible mid-animation.
2. **Wound over-exclusion** — hull spheres near a wound are *dropped* (`WOUND_CLEARANCE 0.05`, `occluder-hull.ts:203-210`) from both hulls. That's correct for the march-bound occluder hull but wrong for the shadow twin: a sphere overlapping a crater is harmless in a shadow map, and dropping it bites holes in the shadow silhouette (the file's own doctrine, L72: "a hole reads as broken").
3. **Shoulder socket pop** — animation layers displace the shoulder points against the chest anchors (gait counter-sway `gait.ts:549-579` opposite signs, attack `shoulderDrive` ±0.06 `attack.ts:244-257`, stagger full-amp vs 0.6× chest `stagger.ts:258-298`, hop +0.06). The torso ellipsoid only just contains the shoulder ball at rest, so these pops the arm ball out of the torso intermittently — visible in the character AND inherited by the hull/shadow.

The screen-space fake the user asked about is viable: a **screen-space contact-shadow pass** in the post-aa chain (VHS wiring pattern), marching scene depth toward the flashlight. It produces shadow exactly matching the on-screen silhouette right at the character–surface junction — where proxy mismatch/desync is most visible — and complements the shadow map beyond.

## Tasks (in order)

### 1. Hold the shadow hull on held-flesh frames (root fix, ~10 LOC)
- `occluder-hull.ts:429-436`: extend `update` opts with `shadow?: boolean` (default true, mirroring the existing `occluder` skip); when false, skip the twin's `fillInstances` so it keeps the previous tick's instances.
- `game-main.ts:3783`: pass `shadow: !(sdfLayer.halfRate && sdfLayer.willHold)` — same hold condition the visual pose uses (L3756). Keep `outerHull` (march bound) updating every tick unchanged.
- Test in `occluder-hull.test.ts`: `shadow:false` retains prior twin count/instances while occluder rebuilds.

### 2. Stop wound exclusion from holing the shadow silhouette (~15 LOC)
- `occluder-hull.ts:435`: build the shadow twin with `wounds = []`; keep the occluder build's exclusions untouched (march-bound correctness is load-bearing there).
- Test: a wound that drops occluder spheres leaves the shadow twin's spheres in place.

### 3. Shoulder socket clamp (character + hull continuity, ~30 LOC)
- `motion.ts` compose (after all layers combine, before `applyRig` consumes): clamp each shoulder offset relative to the chest offset — `delta = shoulder − chest`; if `|delta| > SOCKET_MAX` (~0.045 m, documented tuning const, tighter lateral component), rescale the shoulder offset back toward the chest offset. Below-cap motion (most sway, most of every attack) is untouched; only the pop is capped.
- Add an A/B tuning seam (console param) like the existing `setShadowSpan` precedent so the owner can compare in one frozen load.
- Tests in `motion.test.ts` (plus stagger/attack extremes): relative shoulder–chest displacement never exceeds the cap; rest/idle pose bit-identical when under the cap.

### 4. Screen-space contact-shadow stage (the cheap fake, ~200 LOC)
Follows the VHS wiring pattern exactly (`post-vhs.ts` + `post-aa.ts:785-813`):
- New `post-sscs.ts`: WGSL stage — reconstruct world pos from scene depth, march ~8 steps toward the flashlight position over a short range (~0.8 m, tunable), softly darken where a sample's depth beats the ray depth. Skip marched-flesh pixels via `sdfLayer.marchTarget` alpha (≥1 = level pixel) so bodies never self-darken.
- `post-aa.ts`: attach a `DepthTexture` to `sceneTarget` (exact precedent: `sdf-layer.ts:661` — an attachment isn't sampleable, a DepthTexture is); new stage slot between the chain and FXAA (pre-lens, so fisheye never enters the math); uniforms + `setSscs()` setter; all-off path must not bind the material (L747-757 parity rule).
- `game-main.ts`: per-frame uniform feed (camera view-proj + inv, `flashlight.spot.position`); `?sscs=` URL param + console setter; gated off in deferred/field modes initially (legacy ship path only).
- **Default ON** with `?sscs=off` escape (this pass *is* the requested fix; one flag flips if captures disagree). Strength capped ~0.35 so it reads as contact occlusion layered on the shadow map rather than a second key shadow.
- New `post-sscs.wgsl.test.ts` following `post-vhs.wgsl.test.ts`.

## Risks / notes
- DepthTexture on `sceneTarget` must track resize (field targets show the pattern); WebGPU depth-format sampling has in-repo precedent (goo layer, interleave).
- The flesh mask is stale by one frame on hold frames — acceptable for a soft mask.
- Tasks 1–3 also improve the deferred path for free (same hull feeds `deferred-shadows.ts`); task 4 ships legacy-only first.
- The shoulder clamp slightly tightens animation extremes at the cap — tuning constant is documented and A/B-able; the alternative (widening the torso socket) changes the accepted silhouette and is not proposed.
