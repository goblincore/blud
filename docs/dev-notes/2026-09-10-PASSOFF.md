## 4. Traps that each cost real time this session — do not repeat

1. **READ THE CONSOLE AT LOAD.** An entire afternoon of measurement went into a bug
   whose cause was printed on every page: `THREE.TSL: Input 'deliberately' not
   found`. A compiler error is not findable by measurement.
2. **A `//` comment inside a WGSL parameter list becomes a phantom input.** Three's
   parser sweeps `/name\s*:\s*type/` including comments. Pinned now, and it was the
   SECOND instance of the class (`march.wgsl.test.ts` had the first).
3. **Backticks inside a WGSL template literal** break the TypeScript parse. Hit twice.
4. **`BENCH_LEGS` naming a leg that does not exist SILENTLY measures `baseline`.** A
   whole experiment (the ray sweep) produced a confident, flat, meaningless table
   this way. Use `BENCH_PRELUDE` for one-off overrides.
5. **A cross-boot hash comparison is never evidence.** Two boots disagree at h/2 as
   well — the two-state branch. Same-session, same-parity, no-step-between reads are
   bit-stable; anything else is not.
6. **A diagnostic whose value is absurd is telling you the READER is broken.** The
   output readback returned `[8781, 8992, 9230, 15360]` on an rgba32f target (0-1
   range) and reported "0% surfaces" at h/2 — the WORKING config. It took hours to
   stop explaining it away. `readOutputTarget()` is still broken and its numbers are
   disabled in the diag; use `presentedShot()`.
7. **A confident wrong verdict in a tool is worse than no verdict.** Fix the tool's
   output, not just your conclusion — the diag was still printing the wrong verdict
   after I knew it was wrong.
