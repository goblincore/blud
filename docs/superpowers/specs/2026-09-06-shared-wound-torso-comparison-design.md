# Shared wound torso comparison

Scope follows the accepted bounded investigation in `docs/dev-notes/2026-09-06-sdf-session-handoff.md`: compare torso intact/light/heavy as a bounded analytic cutter preset and a shared sampled preset before migrating the older mutable cache pipeline. Existing gameplay remains the control. The two quick shader edits are a separate commit.

Use one immutable preset library with three severity IDs. Light uses one sphere cutter; heavy uses a fixed union of two overlapping spheres for an irregular cavity. Intact has zero-radius cutters at the same centers, allowing a continuous growth transition without interpolating from an arbitrary far-distance sentinel. Cavity appearance is intentionally simpler than the old accumulated stamps. This first slice has one torso wound region, no region-overlap combinatorics, and no claim of full game integration.

Both evaluators consume identical authored primitives, local coordinates, and severity IDs. The analytic path has at most two cutter evaluations per endpoint. The sampled path bakes the same cutters once into a shared immutable R32F atlas; it derives the value and trilinear gradient from the same eight corners. Quantization is f32 in this first comparison. A conservative Lipschitz bound is derived from the stored corner differences; the represented trilinear field is the actual candidate geometry. Its approximation to the analytic source is measured separately. No claimed exact-SDF property or zero safe-step floor is inherited from the old cache.

An actor owns current/target/queued severity IDs and a transition timestamp. At most two endpoints are sampled. A hit during a transition queues the greatest pending severity; it does not materialize a blended source volume or start a three-endpoint blend. The transition lasts 160ms. Severity never decreases; heavy hits are allocation-free. Reset/recycle resets the IDs only. Library lifetime is separate from actor lifetime.

Validation uses CPU tests for bounded state, transitions, sharing, interpolation derivatives, and sample error. A small real-GPU torso comparison renders the same preset with both representations, verifies finite output and coherent cavities, and records library memory and actual read/evaluation counts. Correctness and memory evidence remain separate from frame timing. Performance under current system load is not an acceptance claim. The combat goal remains stable 30fps, but encounter load/resolution and representative impact/gib/bake gates are required before enabling anything in the game.

The older `codex/zoned-wounds-visual-fix` branch is a source of cache-frame and lifecycle lessons, not a baseline to merge wholesale: it predates current analytic normals and chunk workers. A later game adapter must preserve existing hit/sever decisions, moving owner frames, detached piece state, mesh-bake source fields, reset/recycle, and unsupported-region fallback. Shared storage alone is not a sampling speedup.
